# 돌쇠 — UI 디자인 명세 (handoff)

작성일: 2026-07-18 · 기준 설계서: `docs/superpowers/specs/2026-07-18-local-llm-desktop-mvp-design.md`

이 문서는 개발자가 그대로 구현할 수 있는 수준의 치수·색상·상태 규칙을 정의한다.
살아 있는 목업은 `docs/design/mockups/mockup.html`이며, 이 문서의 모든 수치는 목업 CSS와 일치한다.
목업은 `mockup.html?state=<상태>&theme=<light|dark>`로 14개 상태를 재현할 수 있다(4절 표 참조).

## 1. 디자인 방향 비교와 추천

| | A. 계기판 (Instrument) | B. 서재 (Reading Room) | C. 워크벤치 (Workbench) |
|---|---|---|---|
| 성격 | 운영 도구. 텔레메트리가 1급 시민 | 독서 몰입. 기술 정보 최소화 | IDE형. 모든 패널 상시 노출 |
| 상태 표시 | 하단 상태바에 모노스페이스 수치 상시 | 호버 시에만 노출 | 우측 패널에 상세 노출 |
| 장점 | "조용한 운영 도구" 브리프에 정확히 부합, Windows 11과 조화 | 대화 가독성 최고 | 파워유저 정보 밀도 |
| 단점 | 자칫 밋밋함 | "기술 정보 충분히 제공" 요구 약화 | 1024×700에서 파탄, YAGNI 위반 |

**추천: A안 (계기판).** 시그니처는 하단 28px **런타임 계기판 상태바** — 모델 상태점, 백엔드,
tok/s, 토큰 수, 컨텍스트 사용량을 모노스페이스 수치로 상시 표시하고, 생성 중에는 속도 값이
강조색으로 살아 움직인다. B안의 메시지 행간(1.65)과 C안의 도킹형 설정 패널(토글식)을 부분 수용했다.

**의도적으로 배제한 것**: 중첩 카드, 그라데이션, 8px 초과 라운드, 보라색 팔레트, 마케팅형 헤드라인,
장식용 그림자(그림자는 오버레이 요소에만 허용).

## 2. 디자인 토큰

구현 시 CSS 커스텀 프로퍼티 이름을 그대로 사용한다. 다크 모드는 `<html>`에
`data-theme="dark"`를 지정한다 (`document.documentElement.dataset.theme`).

색 배분 원칙: teal은 "정상 동작·주 동작"에만, amber는 "재로드·주의"에만, red는 "오류·삭제"에만 쓴다.
한 화면에서 teal이 지배하지 않도록 넓은 면적은 항상 뉴트럴로 유지한다.
기능적 정보(메트릭 라인, 비활성 입력창의 사유 placeholder)는 `--text-2` 이상을 쓴다.
`--text-3`는 타임스탬프·힌트·라벨 등 없어도 흐름이 성립하는 메타 정보에만 쓴다.

### 2.2 타이포그래피

```css
--font-ui: "Pretendard Variable", Pretendard, "Segoe UI Variable Text", "Segoe UI",
           "Apple SD Gothic Neo", "Malgun Gothic", sans-serif;
--font-mono: "Cascadia Mono", "SF Mono", Consolas, "D2Coding", monospace;
```

- Pretendard 번들을 권장(라이선스 SIL OFL). 미번들 시 Windows는 Segoe UI + Malgun Gothic으로 동작.
- Cascadia Mono는 Windows 11 기본 탑재, macOS는 SF Mono로 폴백.
- 모든 수치(tok/s, 토큰 수, 컨텍스트)는 `--font-mono` + `font-variant-numeric: tabular-nums`.

| 토큰 | 크기 | 용도 |
|---|---|---|
| `--fs-11` | 11px | 메트릭 라인·캡션·세션 메타·힌트 |
| `--fs-12` | 12px | 보조 텍스트·상태바·패널 라벨·옵션 라벨 |
| `--fs-13` | 13px | 기본 UI·버튼·세션 제목 |
| `--fs-14` | 14px | 메시지 본문·대화 제목·모달 제목 |
| `--fs-16` | 16px | 설정 패널 제목 |
| `--fs-20` | 20px | 빈 상태 제목 |

행간: 기본 UI 1.45 · 사용자 메시지 1.6 · 어시스턴트 메시지 1.65 · 빈 상태 제목 1.4 ·
설명형 문단(빈 상태·모달·모델 메타 1.6, 오류 본문 1.55, 파일명·패널 안내 1.5).

웨이트는 400(본문), 500(세션 제목·버튼), 600(제목·강조) 3단만 사용한다.
상태바 라벨과 패널 섹션 제목은 10~11px, `letter-spacing: .05~.06em`, 대문자(영문일 때), `--text-3`.

### 2.3 간격·반경·그림자

- 간격: 4px 그리드 — `4 / 8 / 12 / 16 / 20 / 24 / 32`
- 반경: `--r-control: 4px` (버튼·인풋·세션 아이템), `--r-container: 6px` (입력창·메시지·모달·오류 블록·팩 행).
  예외: 진행바·재로드 뱃지 2px, 상태점·스피너 원형. 그 외 라운드 금지.
- 그림자: `--shadow-overlay` 하나뿐이며 오버레이 설정 패널·모달에만 적용. 본문 요소에 그림자 금지.

### 2.4 모션

| 대상 | 규칙 |
|---|---|
| 스트리밍 커서 | `blink 1s step-end infinite` (50% opacity 0) |
| 생성 중 상태점 | `pulse 1.2s ease-in-out infinite` (50% opacity .35) |
| 로딩 스피너 | `spin 0.9s linear infinite` |
| 설정 패널 (도킹) | `width 160ms ease-out` (0 ↔ 320px, 내부는 320px 고정 래퍼로 리플로 방지) |
| 설정 패널 (오버레이) | `transform 160ms ease-out` (translateX(100%) ↔ 0) |
| 호버 배경 | 트랜지션 없음 (즉시) — 도구다운 반응성 |
| `prefers-reduced-motion` | 커서·펄스·스피너·패널 트랜지션 모두 비활성 |

그 외 애니메이션은 추가하지 않는다.

## 3. 메인 화면 레이아웃 (1440×900 기준)

목업: `mockups/main-1440x900-light.png`, `mockups/main-1440x900-dark.png`

```
+-----------+----------------------------------------------+- - - - - -+
| 사이드바    | 헤더 48px                                     | 설정 패널   |
| 264px     +----------------------------------------------+  320px    |
|           | 메시지 스크롤 영역                              | (토글)     |
|           |   중앙 칼럼 max 760px                          |           |
|           +----------------------------------------------+           |
|           | 입력 영역 (같은 760px 칼럼)                     |           |
+-----------+----------------------------------------------+- - - - - -+
| 상태바 28px (전체 폭)                                                  |
+----------------------------------------------------------------------+
```

- 창 타이틀바는 OS 네이티브를 사용한다(커스텀 타이틀바 없음).
- 상태바는 사이드바·패널보다 아래 전체 폭. 본문 그리드는 `grid-template-rows: 1fr 28px`.

### 3.1 사이드바 (264px 고정)

| 요소 | 치수 | 비고 |
|---|---|---|
| 헤더 행 | 높이 48, 패딩 0 12 | 앱 마크 20px + 앱 이름 13px/600 + 새 대화 아이콘 버튼 |
| 새 대화 버튼 | 30×30 아이콘 버튼 | Lucide `square-pen`, 툴팁 "새 대화" |
| 검색 인풋 | 높이 28, radius 4 | `--bg-inset`, Lucide `search` 14px, placeholder "대화 검색" |
| 세션 아이템 | 패딩 8 8 8 12, radius 4, 간격 2 | 제목 13px/500 1줄 말줄임 + 메타 11px |
| 활성 세션 | `--bg-active` + 좌측 보더 2px `--accent` | |
| 생성 중 세션 | 메타에 14px 스피너 + "생성 중" (accent, 500) | 비활성 세션이어도 표시 |
| 큐 대기 세션 | 메타 텍스트 "대기 중" (`--text-3`, 스피너 없음) | 슬롯이 가득 찬 상태의 요청 |
| 하단 푸터 | 높이 36, 상단 보더 | "진단" 버튼 (Lucide `activity`), 진단 화면 표시 중 `--bg-active` |

세션 우클릭(또는 호버 `⋯` 버튼) 메뉴: 이름 변경 / 대화 초기화 / 삭제. 삭제는 red 텍스트 + 확인 모달.

세션 삭제 규칙:
- 활성 세션을 삭제하면 목록의 다음 세션을 활성화하고, 세션이 없으면 새 대화를 자동 생성한다.
- 생성 중(또는 대기 중) 세션의 삭제·초기화 확인 모달에는 "진행 중인 생성이 취소됩니다." 문장을
  본문에 병기하고, 확인 시 취소 완료 후 트랜잭션으로 삭제한다.

### 3.2 대화 헤더 (48px)

좌→우: 대화 제목(14px/600, 말줄임, 클릭 시 인라인 이름 변경) · spacer · **모델 칩** ·
구분선(1×16px) · 대화 초기화 아이콘 버튼(Lucide `eraser`) · 설정 토글(Lucide `sliders-horizontal`,
`aria-pressed` 토글이므로 이름은 상태 중립적인 "설정"으로 고정).

**모델 칩** — 모델 선택의 상시 진입점:
높이 30, max-width 300(축소 시 200), 테두리 `--border`, radius 4.
구조: Lucide `box` 14px + 모델명(12px/500, 말줄임) + Lucide `chevron-down`.
클릭하면 OS 파일 선택기(.gguf 필터)를 연다.

| 모델 칩 상태 (클래스) | 표시 |
|---|---|
| 미선택 (`empty`) | "GGUF 모델 선택…" (`--text-2`, 400) |
| 로딩 중 (`loading`) | box 아이콘 대신 스피너 + 파일명 + `64%` (mono, accent). 클릭 무시(`pointer-events: none`) |
| 준비/생성 | 파일명 (`--text-1`, 500) |
| 오류 (`error`) | 파일명 + 테두리 `--red` |

로딩 중 다른 모델 선택은 칩이 비활성이므로 불가하다. 로딩을 중단하려면 중앙 로딩 카드의
[로드 취소] 버튼을 쓴다(3.10 로딩 카드 참조).

### 3.3 메시지 영역

- 칼럼: `max-width: 760px`, 중앙 정렬, 패딩 24 32, 메시지 간 `gap: 24px`.
- **사용자 메시지**: 우측 정렬 블록. `--bg-inset`, radius 6, 패딩 10 14, max-width 640px,
  14px/1.6. 아래에 타임스탬프 11px `--text-3`.
- **어시스턴트 메시지**: 배경 없는 플레인 텍스트(문서형). 14px/1.65.
- 모든 텍스트에 `overflow-wrap: break-word; word-break: break-word; white-space: pre-wrap`
  — 긴 URL·긴 모델명·공백 없는 토큰이 레이아웃을 깨지 않게 하는 필수 규칙.
- **메트릭 라인** (어시스턴트 완료 메시지 하단): mono 11px `--text-2`,
  `42.1 tok/s · 프롬프트 214 · 생성 164 토큰 · 3.9s`. 스트리밍 중에는 accent 색으로 라이브 갱신.
  구분점(`·`)은 `--border-strong`.
- **스트리밍 커서**: 텍스트 끝 7×15px `--accent` 블록, blink.
- **중지 라벨** (취소된 메시지 하단): 12px `--text-2`, 채워진 사각 아이콘 12px +
  "생성이 중지되었습니다 · 토큰 87개 생성됨". 부분 생성 텍스트는 유지한다.
- **중단 라벨** (앱 재시작 후 `streaming` 잔존 메시지): 같은 스타일, 문구
  "생성이 중단되었습니다 · 토큰 87개 생성됨".

### 3.4 인라인 오류 블록

메시지 위치에 렌더링. 좌측 보더 2px `--red`, 배경 `--red-bg`, radius `0 6px 6px 0`,
패딩 12 16, max-width 640.
- 제목: 13px/600 `--red` + Lucide `triangle-alert` 14px
- 본문: 12px `--text-2` — 원인과 오류 코드(`LLW_E_*`)를 명시
- 액션 행: 세컨더리 버튼들 (예: "CPU로 전환 후 다시 로드" / "다시 시도")

오류 카피 규칙: 사과하지 않고, 원인 → 해결 순서로 쓴다.

| 오류 유형 | 제목 | 액션 |
|---|---|---|
| GGUF 로드 실패 | 모델을 로드하지 못했습니다 | 다른 모델 선택… / 다시 시도 |
| 메모리 부족 | 메모리가 부족합니다 | GPU 레이어 줄이기 / CPU로 전환 후 다시 로드 |
| 백엔드 초기화 실패 | CUDA(Vulkan) 백엔드를 초기화하지 못했습니다 | CPU로 전환 후 다시 로드 / 다시 시도 |

세 유형 모두 동일한 오류 블록 컴포넌트를 재사용한다(목업은 백엔드 초기화 실패를 대표로 렌더).

오류 이후 흐름:
- **다시 시도**: 동일 파라미터로 로드/생성을 재실행한다. 기존 오류 블록은 제거 후 진행하고,
  다시 실패하면 새 오류 블록으로 교체한다(누적하지 않음).
- **생성 중 오류**: 취소와 동일하게 부분 생성 텍스트를 유지하고 그 아래에 오류 블록을 붙인다.
- **귀속**: 오류 블록은 오류가 발생한 요청이 속한 세션의 메시지 타임라인에 표시·영속한다
  (`messages`의 오류 상태 활용). 백그라운드 세션의 오류는 사이드바 스피너가 사라지는 것으로만
  현재 화면에 드러난다.
- **로드 실패 복귀**: 이전 모델이 아직 메모리에 있으면 그 모델로 계속 동작하고,
  이미 언로드된 뒤 실패했으면 "모델 없음" 상태로 복귀한다.

### 3.5 입력 영역 (컴포저)

- **전송 버튼**: 32×32, radius 4, `--accent-solid` 배경, Lucide `arrow-up` 16px.
  입력이 비었으면 disabled (`--bg-active` 배경 + `--text-3` 아이콘).
- **중지 버튼**: 전송 버튼과 같은 자리 교체. 32×32, 테두리 1px `--border-strong`,

### 3.6 상태바 (28px, 전체 폭) — 시그니처

좌측 상태 클러스터: 상태점 8px + 상태 텍스트 12px/500 + 모델 파일명 12px `--text-2` (max 300px 말줄임).
로딩 중에는 60×3px 미니 진행바 추가.

우측 텔레메트리 클러스터: 항목마다 `라벨(10px 대문자) + 값(mono 11px)` 구조,
항목 사이 1px 세로 구분선, 항목 패딩 0 12. **5개 항목은 항상 렌더하고 값이 없으면 `—`로 표기한다**
(상태 전이 시 수평 점프 방지).

| 항목 | 값 예시 | 축소 시(≤1179px) |
|---|---|---|
| 백엔드 | `CUDA · RTX 4070` (실패 시 `CUDA → 실패`) | 유지 |
| 속도 | `42.1 tok/s` | 유지 |
| 토큰 | `프롬프트 214 / 생성 164` | 숨김 |
| 컨텍스트 | `1,847 / 8,192` | 유지 |
| 시간 | `3.9s` | 숨김 |

귀속 규칙:
- 텔레메트리 값은 항상 **현재 보고 있는 세션**의 진행 중(없으면 마지막) 요청 기준이다.
- 속도 값의 라이브 강조(accent/600)는 현재 세션이 생성 중일 때만 적용한다.
- 상태점·상태 텍스트는 전역이다: 생성 중 세션이 1개면 "생성 중", 2개 이상이면 "생성 중 · N".

상태점 색: 미선택 ○(테두리만 `--text-3`) · 준비 ● `--accent` · 로딩/생성 ● `--accent` 펄스 ·
주의 ● `--amber` · 오류 ● `--red`.

### 3.7 설정 패널 (320px)

≥1280px에서는 도킹(본문이 줄어듦), <1280px에서는 오버레이(우측 고정, `--shadow-overlay`, 스크림 없음).
오버레이는 바깥 클릭·X·Ctrl+,·Esc로 닫히고, 창 폭이 1280px 이상이 되면 열림 상태를 유지한 채
도킹 모드로 전환된다.

헤더 48px: "설정" 16px/600 + 닫기 X. 본문 패딩 16(하단 24), 섹션 간 구분선 + 상하 16/20.
섹션 제목: 11px/600, letter-spacing .06em, `--text-3`.

**섹션 1 — 모델**: 파일명 13px/500 `word-break: break-all`(줄바꿈 허용),
메타 12px `--text-2` "llama · Q4_K_M · 4.36 GB · 최대 컨텍스트 32,768",
버튼 [다른 모델 선택…] [모델 언로드] (세컨더리 28px).

**섹션 2 — 런타임**: 3분할 세그먼트 컨트롤(높이 28) CPU / CUDA / Vulkan.
선택됨 = `--accent-subtle` 배경 + accent/600 글자. 미설치 백엔드는 disabled + 툴팁
"Vulkan 런타임 팩이 설치되지 않았습니다". 아래 장치 라인(Lucide `cpu` + 장치명·VRAM),
안내문 11px `--text-3` "런타임을 변경하면 현재 모델을 다시 로드합니다."

적용 시점(일괄형): 세그먼트 클릭은 **선택(pending)**이며 즉시 적용하지 않는다.
적용 전 값과 다르면 패널 푸터가 나타나고, [적용하고 모델 다시 로드]를 눌러야 실제로
언로드·재로드가 실행된다. 세그먼트의 눌림 표시는 pending 선택 값을 따르고,
적용된 값과 다른 동안 섹션 제목 옆에 "재로드" 뱃지를 표시한다.

**런타임 팩 행** (미설치 백엔드가 있을 때): 테두리 `--border`, radius 6, 패딩 12.
헤더 행: 팩 이름 12px/500 + 크기 mono 11px + [설치] 세컨더리 버튼.
설치 중에는 버튼 대신 4px 진행바 + mono 상태 라인 `다운로드 중 | 42% · 49.6 / 118 MB`.
안내문: "서명과 체크섬을 검증한 뒤 다음 시작 시 활성화됩니다. 창을 닫아도 설치는 계속됩니다."
단계는 `다운로드 중 → 검증 중 → 다음 시작 시 활성화` 순으로 상태 라인 텍스트만 교체한다.
실패 시 행 안에 12px `--red` 한 줄 + [다시 시도]로 교체한다.

**섹션 3 — 추론 옵션**: 행 높이 32, 좌측 라벨 12px + 원본 플래그(mono 10px `--text-3`),
우측 숫자 인풋 88×28 (mono 12px, 우측 정렬).

| 라벨 | 플래그 | 기본값 | 유효 범위 | 적용 시점 |
|---|---|---|---|---|
| 컨텍스트 길이 | `--ctx-size` | 8192 | 512 ~ 모델 최대 | **재로드** 뱃지 |
| GPU 레이어 | `--n-gpu-layers` | 32 | 0 ~ 모델 레이어 수 | **재로드** 뱃지 |
| Temperature | `--temp` | 0.7 | 0 ~ 2 | 다음 요청 |
| Top-P | `--top-p` | 0.9 | 0 ~ 1 | 다음 요청 |

| Seed | `--seed` | -1 | -1(무작위) 또는 0 이상 | 다음 요청 |

범위 밖 입력은 blur 시점에 가까운 경계값으로 클램프하고 인풋 아래 11px `--amber` 안내를
1회 표시한다. 재로드 뱃지: `--amber-bg` 배경 + `--amber` 10px/600, radius 2, 패딩 1 5.

**섹션 4 — 고급 설정**: 옵션 검색 인풋(사이드바 검색과 동일 규격, placeholder "옵션 검색") +
런타임 capability/option schema JSON이 제공하는 옵션 행(추론 옵션과 동일 규격).
대표 예: 배치 크기 `--batch-size`(재로드), 스레드 수 `--threads`(재로드),
반복 페널티 `--repeat-penalty`(다음 요청). 안내문: "런타임이 제공하는 옵션 스키마를 기준으로
표시됩니다. 지원하지 않는 값은 저장 시 오류로 표시됩니다." 검색은 라벨·플래그 문자열 부분 일치.

**섹션 5 — 화면**: 테마 세그먼트 컨트롤(높이 28) 라이트 / 다크 / 시스템. 기본값 시스템.

활성 생성이 있으면 클릭 시 재로드 확인 모달(3.8)을 먼저 띄운다.

저장 범위: 추론·고급 옵션은 **모델별 프로필**(`settings_profiles`)에 저장하고 세션은 프로필을

## 5. 반응형 규칙 (데스크톱 최소 1024×700)

Tauri 창: `minWidth: 1024, minHeight: 700`, 기본 `1440×900`.

| 조건 | 규칙 |
|---|---|
| ≥1280px | 설정 패널 도킹 (본문 폭 감소) |
| <1280px | 설정 패널 오버레이 (우측 고정 320px, 그림자, 스크림 없음, 바깥 클릭 시 닫힘) |
| <1180px | 사이드바 264→224px · 상태바 토큰/시간 항목 숨김 · 모델 칩 max 300→200px · 메시지 칼럼 좌우 패딩 32→20px · 상태바 모델명 max 180px |
| 항상 | 메시지 칼럼 `max-width: 760px` 중앙 정렬, 세로 스크롤은 메시지 영역·패널 본문만 |

너비와 무관하게 지켜야 하는 것: 긴 모델 파일명은 칩·상태바에서 말줄임, 설정 패널·진단에서만 전체 줄바꿈 표시.
사이드바는 접지 않는다(1024px에서도 224px 유지가 성립함을 목업으로 확인).

## 6. 상호작용 규칙

### 키보드

| 키 | 동작 |
|---|---|
| Enter | 전송 (비어 있으면 무시) |
| Shift+Enter | 줄바꿈 |
| Esc | 우선순위: 열린 모달 닫기(취소) → 생성 중지 → 오버레이 패널 닫기 |
| Ctrl+N | 새 대화 |
| Ctrl+F | 사이드바 검색 포커스 |
| Ctrl+, | 설정 패널 토글 |

- 포커스 표시: `outline: 2px solid var(--accent); outline-offset: 1px` — 모든 인터랙티브 요소.
- 아이콘 버튼에는 반드시 `aria-label` + 툴팁. 토글 버튼(설정 등)의 이름에는 동작(열기/닫기)을
  넣지 않는다 — 상태는 `aria-pressed`가 전달한다.
- 전송 후 입력창은 비우고 포커스 유지. 중지 후에도 포커스는 입력창.
- 새 메시지 도착 시: 사용자가 맨 아래에 있을 때만 자동 스크롤. 위로 스크롤한 상태면 유지.

### 상태 전이 시 UI 규칙

- 런타임 변경·재로드 옵션 적용: 패널 푸터 버튼 → (활성 생성 있으면) 재로드 확인 모달 →
  취소 완료 → 언로드 → 로드.
- 생성 중 다른 세션으로 이동 가능. 원래 세션은 사이드바에 "생성 중" 표시를 유지한다.
- 한 세션에서는 동시에 1개 생성만 허용(전송 버튼 대신 중지 버튼).
- 전역 슬롯이 가득 찬 상태의 새 요청은 큐에 대기한다: 사이드바 메타 "대기 중",
  해당 세션 컴포저 힌트 "슬롯이 비면 생성을 시작합니다".
- 모델 로드 실패·생성 오류 흐름은 3.4의 규칙을 따른다.

## 8. 구현 지침

### 8.1 스택과 구조

- 기존 스캐폴드: `apps/desktop` (Tauri 2 + React + TypeScript + Vite).
- 토큰은 `src/styles/tokens.css`에 2절 CSS 커스텀 프로퍼티 그대로 정의. 컴포넌트는 토큰만 참조하고 hex를 직접 쓰지 않는다.
- 다크 모드: `document.documentElement.dataset.theme` 토글. 초기값은 OS `prefers-color-scheme` 연동,
  설정 패널 "화면" 섹션에서 라이트/다크/시스템 override.

### 8.4 앱 아이콘 적용

Tauri CLI는 이 저장소에서 `apps/desktop`의 npm devDependency로 설치되어 있으므로:

```
cd apps/desktop
npm run tauri icon ../../design/app-icon-1024.png
```

출력은 `apps/desktop/src-tauri/icons/`에 생성되어 `tauri.conf.json`의 `bundle.icon` 목록과 일치한다.

원본: `design/app-icon.svg` (색상) · `design/app-icon-mono.svg` (단색 컷아웃) ·
`design/app-icon-1024.png` (투명 배경 1024×1024, 위 명령의 입력).

아이콘 개념: **"칩 속의 책"** — 칩 실루엣(로컬 연산)이 열린 책(지식)을 담는다.
색: 칩 `#0E7C71`, 책 `#F2F7F5`. 텍스트·가는 선·작은 노드 없음. 콘텐츠는 중앙 820px
안전 영역 안에 있어 Windows(모서리까지 사용)와 macOS(스퀘어클 마스크) 모두 대응한다.
비교안과 크기·배경·단색 검증: `docs/design/icon-concepts.png` (원본 `mockups/icons.html`).

## 9. 미결정 사항 (구현 전 확인)

1. **Pretendard 번들 여부** — 권장은 번들(용량 +2MB). 미번들이면 Malgun Gothic 폴백으로 자간이 조금 거칠어진다.
2. **사이드바 세션 컨텍스트 메뉴 방식** — 우클릭 메뉴 vs 호버 `⋯` 버튼. 스펙은 둘 다 허용, 목업은 미포함.
3. **오프라인 ZIP 런타임 팩 가져오기의 진입점** — 설정 런타임 섹션 vs 진단 화면. 팩 행의 검증·활성화 규칙은 동일하게 재사용한다.
4. **진단 화면 갱신 주기(5초)의 적정성** — 실측 후 조정 가능.
